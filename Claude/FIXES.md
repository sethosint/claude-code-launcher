# ClaudeLauncher — что починено (2026-07-28, v2)

Собрано и проверено: `dotnet build` → **0 errors, 0 warnings** (net10.0-windows, WPF + XAML).
Прокси проверен запуском на реальном Node: `/health` отвечает, строгий порт работает,
процесс переживает закрытие лаунчера.

---

## 1. Главная причина: gateway для Completions не стартовал

`ProcessRunner` запускал прокси так:

```
cmd.exe /c "node" "C:\...\CompletionsProxy\server.js" --no-launch
```

По документированному поведению `cmd /?` кавычки сохраняются **только** если в строке
ровно два символа `"` и между ними — имя исполняемого файла. Здесь кавычек четыре, поэтому
cmd срезает **первую и последнюю** кавычку и пытается выполнить:

```
node" "C:\...\server.js --no-launch
```

Такой команды нет → cmd выходит с кодом 1 через ~10–15 мс → лаунчер 25 секунд ждёт
health-check и показывает «gateway failed to start».

**Kiro работал именно потому, что у него ровно две кавычки:**
`cmd /c "C:\...\omniroute.cmd" --no-open` → правило срабатывает, кавычки сохраняются.

### Что сделано
- **Новый `Services/Process/ExecutableResolver.cs`** — сам ищет `node` по `PATH` + `PATHEXT`
  и по типичным местам установки (`Program Files\nodejs`, `%LOCALAPPDATA%\Programs\nodejs`,
  `%APPDATA%\npm`, nvm/fnm). `node.exe` теперь запускается **напрямую, без cmd.exe** — кавычки
  ломать больше некому.
- **`CommandShellHelper.BuildShellArguments`** — для `.cmd`/`.bat` (Kiro) используется
  канонически безопасная форма `cmd.exe /s /c "…"` (вся команда во внешних кавычках).
- **`GatewayService`** больше не «пробует запустить» кандидата через cmd для проверки наличия,
  а использует тот же resolver, что и запуск. То есть «найдено» = «точно запустится».

## 2. Рабочая папка прокси
`GatewayConfig.WorkingDirectory` (новое поле) → для Completions это папка `CompletionsProxy`.
Node теперь всегда находит свои `node_modules`, откуда бы ни стартовал лаунчер
(ярлык, автозапуск, «Закрепить на панели задач»).

## 3. Порт больше не «уплывает»
`server.js` умел молча занимать следующий свободный порт (`4243`, `4244`…), а лаунчер при этом
проверял `4242` и туда же направлял Claude → выглядело как «gateway не поднялся».
Теперь лаунчер передаёт `PORT_STRICT=1`, и прокси либо занимает заданный порт, либо сразу
падает с понятным сообщением.

## 4. Прокси больше не умирает вместе с лаунчером
При `CloseAfterLaunch=true` лаунчер закрывается сразу после старта Claude и закрывает pipe'ы,
которые отдал прокси. Следующая же строка лога = `EPIPE` = смерть прокси прямо во время работы
Claude. В `server.js` добавлена защита от `EPIPE`/`ERR_STREAM_DESTROYED`. Проверено тестом:
после закрытия pipe'ов родителем прокси продолжает обслуживать запросы.

## 5. Claude Code больше не спрашивает про API-ключ
`preConfigureClaude()` (запись `hasCompletedOnboarding`, `customApiKeyResponses` в `~/.claude.json`)
раньше выполнялась **только** когда прокси сам запускал Claude. Теперь она выполняется и в
режиме `--no-launch`, а C# передаёт ровно тот плейсхолдер-ключ (`copilot-proxy`), который прокси
и добавляет в approved. Плюс к Claude уходят `ANTHROPIC_API_URL` и `ANTHROPIC_API_KEY`
(раньше был только `ANTHROPIC_AUTH_TOKEN`), чтобы ни один запрос не ушёл на api.anthropic.com.

## 6. ID модели больше не «чинится» ошибочно
`CompletionsProvider.NormalizeModelId` срезал префикс вендора:
`anthropic/claude-sonnet-4` → `claude-sonnet-4`. Но список моделей в настройках приходит
**из того же эндпоинта**, куда потом уходит запрос, то есть ID уже правильный. Для
OpenRouter-совместимых шлюзов префикс обязателен, и срез превращал валидную модель в
«model not found». Теперь ID передаётся как есть.

## 7. Мелочи, которые тоже были багами
- `ProviderFactory.CreateAlternate` не копировал `CompletionsGateway` → при автопереключении
  провайдера настройки прокси (порт/таймаут) терялись. Исправлено.
- Health-check теперь дополнительно проверяет тело ответа (`HealthResponseMustContain`), чтобы
  чужой сервис на 4242 не был принят за наш прокси.
- Валидация окружения заранее проверяет наличие `CompletionsProxy\server.js` и
  `node_modules\express` и говорит об этом сразу, а не через 25 секунд таймаута.
- В `config.json` добавлен блок `CompletionsGateway` (порт/таймаут прокси) — теперь его видно
  и можно править.
- Флаг `--no-launch` в `server.js` раньше игнорировался (работала только переменная `NO_LAUNCH`).

## 8. UI: последний шаг в «Activity» больше не обрезается
- Чек-лист жил в контейнере с жёстким `MaxHeight="220"`; при длинной строке detail нижние шаги
  («Launch Claude», «Ready») уходили за край. Теперь чек-лист и лог делят карточку
  пропорционально (2 : 1) со своими скроллами и минимальными высотами.
- Добавлен `ActiveStepIndex`: активный (или упавший) шаг **автоматически прокручивается в зону
  видимости**.
- Текст ошибки теперь остаётся на самом упавшем шаге и подсвечивается красным (раньше detail
  исчезал в момент падения — именно там, где он нужнее всего).
- Окно: `720` по высоте, `MinHeight` снижен до `620`, чтобы верстка не ломалась на ноутбуках.

## Что стоит проверить в своих настройках

В `config.json` сейчас:

```
"Completions": {
  "BaseUrl": "https://openrouter.ai/api/v1/",
  "ApiKey":  "sk-cp_…",
  "Model":   "anthropic/claude-sonnet-4"
}
```

Ключ формата `sk-cp_…` — это ключ **completions.me (deprecated)**, а BaseUrl указывает на **OpenRouter**.
Один из двух вариантов надо привести в соответствие:

- completions.me (deprecated): `BaseUrl` = `https://www.completions.me (deprecated)/api/v1`, модель вида `claude-sonnet-4.5`;
- OpenRouter: ключ вида `sk-or-v1-…`, модель с префиксом `anthropic/…` (теперь префикс сохраняется).

Иначе gateway поднимется, но upstream ответит 401.

## Если что-то всё же не стартует
Меню «…» → **Open Logs**. Туда теперь построчно пишется собственный вывод процесса gateway
(stack trace Node, занятый порт, неверный ключ) плюс строка `Resolved "node" to "…"` —
сразу видно, что именно запускалось.

## v2 (после первого прогона на твоей машине)

- **Мгновенная диагностика gateway.** `IProcessRunner` теперь возвращает живой handle
  (`StartedProcess`): лаунчер видит, что процесс умер, **сразу**, а не через 25 секунд таймаута,
  и показывает в UI его собственный последний вывод (ANSI-коды вырезаются). То есть вместо
  «Gateway failed to start» будет, например: «The gateway process exited immediately (exit code 1,
  after 12 ms). Error: Cannot find module 'express'».
- **`ProcessRunner`** больше не может упасть с `No process is associated with this object`:
  ExitCode читается до `Dispose()`, сам `Dispose()` обёрнут в try/catch, плюс перед ним даётся
  1 с на дочитывание stdout/stderr (иначе последние строки — как раз причина падения — терялись).
- **Вёрстка Activity просчитана по пикселям** (DIP-арифметика WPF, 100% масштаб):
  окно 740 → карточка Activity 376px → чек-лист 210px при нужных 168px (7 строк × 24px).
  Отступ строки 10 → 6, разделители 14/16 → 10/12, ряды 5\* : 2\* с `MinHeight` 176/50.
  При сжатии окна первым уступает место лог, а не чек-лист; `ClipToBounds` не даёт содержимому
  вылезти за карточку. Окно: `Height=740`, `MinHeight=560`.

## v3 (после первого успешного запуска Claude на Completions)

**1. Предупреждение «Both ANTHROPIC_AUTH_TOKEN and ANTHROPIC_API_KEY set».**
Лаунчер выставлял обе переменные. Теперь Claude Code получает только
`ANTHROPIC_AUTH_TOKEN`, а `ANTHROPIC_API_KEY` передаётся пустым — в .NET пустое
значение означает «удалить переменную», так что заодно вычищается и настоящий
`ANTHROPIC_API_KEY`, если он есть в системе (иначе он «протекал» бы в сессию).

**2. «Claude Sonnet 4 retired June 15, 2026».**
В `ANTHROPIC_MODEL` уходил id вместе с префиксом каталога
(`anthropic/claude-sonnet-4`), и Claude Code определял модель по этой строке.
Теперь клиенту отдаётся чистый id (`claude-sonnet-4.6`), а прокси получает
точный id из настроек через `FORCE_MODEL` — то есть на upstream уходит ровно та
модель, что выбрана в Settings, включая её префикс. Дополнительно выставляется
`ANTHROPIC_SMALL_FAST_MODEL`, иначе фоновые вызовы Claude Code уходили бы с
haiku-id, которого у провайдера может не быть.

**3. `config.json` больше не затирается сборкой.**
Он же — живой файл настроек (Settings пишет туда ключи и модель), а стоял
`CopyToOutputDirectory=PreserveNewest`, из-за чего каждый ребилд возвращал
шаблон из проекта. Теперь файл только **создаётся, если его нет** (target
`SeedDefaultConfig`).

**4. Вёрстка Activity на idle-экране.**
Пустое состояние было блоком «кружок 44px + заголовок + подпись» (~103px) по
центру области логов, которая может быть высотой 40px — его и срезало нижним
краем карточки. Теперь это одна строка-пилюля (~30px), которая помещается при
любом размере окна и обрезается многоточием при узком окне.
Сам чек-лист больше не делит карточку в фиксированной пропорции: он занимает
ровно столько, сколько нужно его строкам (`Auto`), а всё остальное достаётся
логам — поэтому в середине карточки больше нет мёртвой пустоты. Сверху он
ограничен `(высота карточки − 42) × 0.66` (`RatioConverter`): в маленьком окне
чек-лист скроллится внутри себя, а не обрезается. Минимальная высота окна
поднята до 700 — при ней все семь шагов видны без скролла.

## v4 — редизайн + функции настоящего лаунчера

### Почему 401 не ушёл после смены Base URL (главный баг)

`GatewayService` сначала пингует `localhost:4242/health` и, если оттуда
приходит здоровый ответ, **переиспользует уже запущенный прокси**. Но прокси,
поднятый в прошлой сессии, продолжает работать с теми переменными, с которыми
его запустили: старый endpoint, старый ключ, старая модель. Поэтому смена
Base URL в Settings не имела никакого эффекта, пока процесс не убьёшь руками.

Теперь `/health` прокси отдаёт `saasUrl`, `model` и `pid`, а лаунчер сравнивает
их с текущими настройками. Не совпало — прокси корректно останавливается через
новый `POST /shutdown` (только с localhost), лаунчер дожидается освобождения
порта и поднимает новый. Если старый прокси не умеет `/shutdown` (сборка до
v4), лаунчер завершает его по `pid`; если и это не вышло — показывает понятную
ошибку вместо тихого запуска Claude «не туда».

### Ключ проверяется до запуска Claude, а не внутри него

`GET /models` у обоих каталогов (openrouter.ai и completions.me (deprecated)) **публичный**:
отвечает 200 вообще без ключа. Поэтому старая проверка «провайдер доступен»
пропускала и чужой ключ, и невалидный — а первым признаком проблемы был сырой
`{"error":{"message":"Missing Authentication header","code":401}}` уже внутри
сессии Claude, где лаунчер объяснить ничего не может.

Новый `ProviderAccessService` (шаг «Check provider access»):
1. офлайн-проверка формы ключа — `sk-or-v1-…` на completions.me (deprecated) или `sk-cp_…`
   на openrouter.ai не заработают никогда, это ловится без сети;
2. настоящий авторизованный запрос — бесплатный `GET /key` у OpenRouter (он же
   отдаёт остаток кредитов, они показываются в панели) либо запрос на один
   токен для остальных OpenAI-совместимых endpoint'ов.

Ответ на запрос-пробу цитируется в панели («Key valid · replied "…"»). Это
самый быстрый способ увидеть, что endpoint — заглушка, отвечающая одним и тем
же текстом на любой запрос, чего не покажет ни один код статуса.

Проверку можно выключить: `Launcher.PreflightAuthCheck = false`.

### Больше нет ложных «Claude Sonnet 4 / Opus 4 retired»

`ANTHROPIC_MODEL` для провайдера Completions больше не выставляется вообще.
Модель на каждом запросе всё равно принудительно ставит прокси (`FORCE_MODEL`),
а эта переменная влияла только на то, к какому семейству Claude Code относит
сам себя — и он определяет это подстрокой, из-за чего `claude-opus-4.6`
опознавался как «Opus 4» и печаталось предупреждение о снятой модели. Запрос на
провода при этом не менялся ни на байт.

### Приватность сессии

Новый флажок «Private session (no telemetry)» (`Launcher.PrivacyMode`, включён
по умолчанию) запускает Claude Code с
`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC`, `DISABLE_TELEMETRY`,
`DISABLE_ERROR_REPORTING`, `DISABLE_BUG_COMMAND`, `DISABLE_AUTOUPDATER` и
`CLAUDE_CODE_DISABLE_TERMINAL_TITLE` (последнее убирает имя проекта из
заголовка терминала). Чего это не делает и не может сделать: скрыть проект от
самого провайдера модели — файлы, пути и вывод команд, которые Claude Code
кладёт в запрос, и есть запрос. Единственный рычаг здесь — какой провайдер
это видит, для чего и нужен переключатель.

Заодно Kiro-провайдер тоже больше не выставляет одновременно
`ANTHROPIC_AUTH_TOKEN` и `ANTHROPIC_API_KEY`.

### Claude запускается в папке проекта

`ClaudeService` передавал `ProcessStartInfo` без `WorkingDirectory`, поэтому
Claude Code наследовал папку лаунчера и каждая сессия открывалась в
`bin\Debug` — то есть Claude не видел проекта вообще. Теперь папка выбирается
в самом лаунчере (`Launcher.WorkingDirectory`), хранится история последних
восьми папок (`Launcher.RecentProjects`), а несуществующая папка не ломает
запуск — просто пишется предупреждение в лог.

### Главное окно переделано

Одноколоночный «мастер» превращён в панель запуска:

* **слева** — что именно будет запущено: проект (+ «Change» и список
  недавних), переключатель провайдера, выбор модели с обновлением списка,
  строка `ROUTE` (`claude → proxy localhost:4242 → openrouter.ai`), состояние
  ключа с кнопкой «Check», флажки поведения и приватности, большая кнопка
  запуска, всегда видимая внизу;
* **справа** — что происходит: статус, прогресс, чек-лист шагов и консоль
  с копированием лога и доступом к файлам логов.

Провайдер, модель и папка проекта меняются прямо здесь и сразу пишутся в
`config.json`; после закрытия Settings окно перечитывает конфиг, чтобы не
затереть только что сохранённые там значения. Панель слева скроллится, поэтому
кнопка запуска не уезжает за край даже в минимальном окне (960×700), а
чек-лист по-прежнему ограничен долей карточки и скроллится внутри себя.
